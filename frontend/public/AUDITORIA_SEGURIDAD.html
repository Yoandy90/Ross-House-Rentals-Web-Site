Auditoría de Seguridad — Ross House Rentals

Realizada: 15 julio 2026 · Alcance: backend FastAPI + web Next.js + app Expo

✅ Lo que ya estaba BIEN: Las claves/API keys NO están expuestas en ningún lado — ni en el código del frontend, ni en los archivos públicos (.html/.md), ni en la app Expo, ni en las respuestas de la API. Vulnerabilidades encontradas y CORREGIDAS

SeveridadProblemaCorrección aplicada
ALTA → ARREGLADA El webhook de Xcel (público, sin login) descargaba cualquier URL que le enviaran, adjuntando nuestro token de Xcel. Un atacante podía robar el token o hacer que el servidor llamara a sistemas internos (SSRF). Ahora solo se descargan URLs de dominios oficiales *.xcelenergy.com por HTTPS. Cualquier otra URL se bloquea y se registra.
ALTA → ARREGLADA La encriptación del Baúl Seguro usaba llaves derivadas de texto que estaba en el código. Si la base de datos se filtraba, se podían desencriptar los números de cuenta bancaria y tarjetas. Se generaron llaves aleatorias fuertes nuevas (VAULT_ENCRYPTION_KEY, VAULT_JWT_SECRET). Se eliminaron todas las llaves "de respaldo" del código: si la llave no está en el entorno, el baúl se niega a operar. El token de sesión del baúl ya no se puede falsificar desde el código.
MEDIA → ARREGLADA El bloqueo tras 5 intentos de PIN del baúl no funcionaba: la verificación de bloqueo ocurría después de comprobar el PIN, así que se podía intentar sin límite (fuerza bruta). Ahora el bloqueo se verifica ANTES de comprobar el PIN. Tras 5 fallos → bloqueo de 15 min real. Muestra intentos restantes y resetea el contador al acertar.
MEDIA → ARREGLADA Un tenant podía pagar $1 y registrar el mes como pagado, porque el monto de la renta se tomaba del cliente. El monto base de la renta ahora se toma SIEMPRE del contrato en el servidor; el cliente no puede alterarlo.
MEDIA → ARREGLADA El webhook de Stripe procesaba eventos sin verificar la firma si faltaba el secreto → se podían falsificar pagos. Ahora rechaza cualquier webhook sin firma verificada (falla cerrado).
MEDIA → ARREGLADA La página de callback de Xcel reflejaba un parámetro sin escapar (XSS reflejado). El valor ahora se escapa como HTML.
BAJA → ARREGLADA El endpoint de subida de imágenes aceptaba cualquier texto como autorización (subidas anónimas de 10MB). Ahora valida que el token JWT sea auténtico antes de aceptar la subida.
